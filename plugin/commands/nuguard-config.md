name: nuguard-config
description: Configure NuGuard — set LLM credentials, target URL, and authentication for this project
allowed-tools: ["Read", "Write", "Bash"]
---

Collect the user's NuGuard configuration and write it to `.claude/nuguard.local.md`.
This file is read by all NuGuard commands and agents to avoid repeating credentials on every call.

## Steps

### 1. Check for existing config

Read `.claude/nuguard.local.md` if it exists so you can show current values as defaults.

### 2. Collect settings interactively

Ask the user for each value. Show the current value in brackets when one already exists.
Mark optional fields clearly — only `llm_api_key` and `target_url` are required.

**LLM settings** (used for SBOM enrichment, analysis, and red-team payload generation):

- **LLM API Key** *(required)* — API key for the LLM provider.
  Accepts any LiteLLM-compatible key (Gemini, OpenAI, Anthropic, Azure, etc.).
  Example: `AIza...`, `sk-...`

- **Model name** *(optional, default: `gemini/gemini-2.0-flash`)* — LiteLLM model string.
  Examples: `gemini/gemini-2.0-flash`, `openai/gpt-4o`, `azure/gpt-4o`, `anthropic/claude-opus-4-7`

- **API Base URL** *(optional)* — Required for Azure OpenAI or self-hosted models.
  Example: `https://my-instance.openai.azure.com`

- **API Version** *(optional)* — Required for Azure OpenAI.
  Example: `2024-05-01-preview`

**Target application** (used for behavioral testing and red-team):

- **Target URL** *(required)* — Base URL of the running AI application.
  Example: `http://localhost:8080`

- **Chat endpoint** *(optional, default: `/chat`)* — Path for sending messages.
  Example: `/api/v1/chat`, `/chat/completions`

**Authentication** — ask which type applies:

  - `none` — no authentication required
  - `bearer_token` — `Authorization: Bearer <token>`
  - `api_key` — custom header with API key
  - `basic` — HTTP Basic (username + password)

  Then collect the relevant credential(s) for the chosen type:
  - Bearer token: the token value
  - API key: the header name (default: `X-API-Key`) and key value
  - Basic: username and password

### 3. Write `.claude/nuguard.local.md`

Create or overwrite the file with this structure (omit empty optional fields):

```
---
llm_api_key: "<value>"
llm_model: "<value>"
llm_api_base: "<value>"
llm_api_version: "<value>"
target_url: "<value>"
chat_endpoint: "<value>"
auth_type: "<none|bearer_token|api_key|basic>"
auth_token: "<value>"
auth_api_key_header: "<value>"
auth_api_key_value: "<value>"
auth_username: "<value>"
auth_password: "<value>"
---

# NuGuard Project Config

Generated by /nuguard-config. Edit manually or re-run the command to update.
Do not commit this file — it contains credentials.
```

### 4. Confirm and remind

Tell the user:
- Which file was written and what values were set (mask secrets — show only first 4 chars + `****`)
- That the file is project-local and should not be committed (`*.local.md` is in `.gitignore`)
- That they can re-run `/nuguard-config` any time to update settings
- That `/nuguard-init` will use these values to generate `nuguard.yaml` if they need a config file on disk
