A clear path forward

One workflow.
Five steps to stronger AI.

Start with source code. Add your application’s policy and an authorized sandbox when you’re ready to test runtime behavior.

Start here · Source code

Know what you’re building.

Turn source code into an AI-SBOM of your assets and data paths. The first scan needs no live target or LLM key.

Read the discovery guide
terminal 
# Map your application from source
nuguard sbom generate \
  --source . \
  --output app.sbom.json
Source → assets → relationships
Your application · Your intent

Put the boundaries in writing.

Use a Cognitive Policy to describe allowed topics, data handling, and restricted actions. Validate it before live testing.

Read the policy guide
terminal 
# Validate your Cognitive Policy
nuguard policy validate \
  --file cognitive_policy.md
Intent → policy → testable controls
Static checks · Risk context

Turn the inventory into insight.

Analyze the AI-SBOM for security issues and relationships that deserve a closer look. Review findings before moving to runtime checks.

Read the analysis guide
terminal 
# Analyze the discovered application
nuguard analyze \
  --sbom app.sbom.json \
  --source .
Inventory → findings → risk context
Authorized sandbox · Runtime tests

Test what the application really does.

Configure your target and test identity, then verify the connection. Run behavior, red-team, or web tests to answer specific security questions.

Set up runtime testing
terminal 
# Verify your configured sandbox first
nuguard target verify \
  --config nuguard.yaml \
  --sbom app.sbom.json
Behavior · red-team · authorized pentest
Release decisions · Shared evidence

Make security part of delivery.

Retain reports, review findings, and use severity gates in CI. Fix confirmed issues and rerun the relevant checks; review coverage gaps alongside results.

Explore release gates
terminal 
# Retain evidence and gate on severity
nuguard scan --source . \
  --output-dir nuguard-reports \
  --fail-on high
Reports → review → fix & retest
